# خانه‌پز | khanepaz.ir

سایت آشپزی و شیرینی‌پزی خانه‌پز. سایت کاملاً **استاتیک** است (HTML + CSS + JS) و همه‌ی محتوا از فایل‌های JSON پوشه‌ی `data/` خوانده می‌شود؛ پس بدون سرور روی گیت‌هاب پیج‌ها اجرا می‌شود.

## ساختار پروژه

```
khanepaz/
├─ index.html              صفحه‌ی اصلی
├─ CNAME                   دامنه‌ی khanepaz.ir برای GitHub Pages
├─ .nojekyll
├─ assets/
│  ├─ css/style.css        همه‌ی ظاهر سایت
│  ├─ js/config.js         تنظیمات (json یا api)
│  ├─ js/api.js            تنها جایی که می‌داند داده از کجا می‌آید
│  ├─ js/app.js            منطق صفحه (رندر، جستجو، کاروسل، مودال…)
│  └─ img/                 عکس‌ها را اینجا بگذارید
└─ data/
   ├─ site.json            متن هیرو، داستان، کاروسل، لینک‌ها
   ├─ categories.json      دسته‌بندی‌ها
   ├─ recipes.json         دستورها
   ├─ tutorials.json       آموزش‌ها
   ├─ gallery.json         تصاویر
   └─ comments.json        نظرات
```

## اجرا روی کامپیوتر

مرورگر اجازه‌ی خواندن JSON از `file://` را نمی‌دهد؛ پس یک سرور ساده اجرا کنید:

```bash
cd khanepaz
python3 -m http.server 8000
# بعد این آدرس را باز کنید: http://localhost:8000
```

## انتشار روی گیت‌هاب

1. یک مخزن جدید بسازید (مثلاً `khanepaz`) و محتوای این پوشه را در شاخه‌ی `main` قرار دهید:
   ```bash
   git init
   git add .
   git commit -m "خانه‌پز: نسخه‌ی اول"
   git branch -M main
   git remote add origin https://github.com/USERNAME/khanepaz.git
   git push -u origin main
   ```
2. در مخزن: **Settings → Pages → Build and deployment**، منبع را **Deploy from a branch** و شاخه‌ی `main` و پوشه‌ی `/ (root)` بگذارید.
3. بعد از چند دقیقه سایت روی `https://USERNAME.github.io/khanepaz/` بالا می‌آید.
4. برای دامنه‌ی `khanepaz.ir`:
   - فایل `CNAME` همین حالا در پروژه هست.
   - در پنل DNS دامنه، چهار رکورد **A** به این آدرس‌ها بسازید: `185.199.108.153`، `185.199.109.153`، `185.199.110.153`، `185.199.111.153` (و برای `www` یک رکورد **CNAME** به `USERNAME.github.io`).
   - در Settings → Pages تیک **Enforce HTTPS** را بعد از فعال‌شدن گواهی بزنید.

## چطور محتوا اضافه کنم؟

فقط JSON را ویرایش کنید؛ کد را لازم نیست دست بزنید.

**دستور جدید** را به `data/recipes.json` اضافه کنید:

```json
{
  "id": "unique-english-id",
  "title": "نام دستور",
  "category": "qazvini-sweets",
  "excerpt": "توضیح کوتاه",
  "time": 60,
  "servings": 6,
  "difficulty": "آسان",
  "rating": 4.5,
  "votes": 10,
  "created": "2026-09-20",
  "featured": false,
  "tags": ["برچسب۱", "برچسب۲"],
  "art": { "emoji": "🍰", "from": "#f4c26b", "to": "#c9743a" },
  "image": "assets/img/my-photo.jpg",
  "ingredients": ["ماده ۱: مقدار"],
  "steps": ["مرحله ۱", "مرحله ۲"],
  "tip": "یک نکته‌ی خانه‌پزی"
}
```

- `category` باید یکی از `slug`های `categories.json` باشد.
- اگر `image` خالی باشد، سایت یک طرح رنگی با ایموجی و بخار نشان می‌دهد؛ اگر آدرس عکس بگذارید، عکس نشان داده می‌شود.
- `featured: true` یعنی در بخش «ویژه‌ها» بیاید. بخش «آخرین‌ها» بر اساس `created` و «بهترین‌ها» بر اساس `rating` خودکار مرتب می‌شود.
- اسلایدهای کاروسل در `site.json` (بخش `carousel`) با `recipeId` به دستورها وصل می‌شوند.

## آماده برای سایت مدیریت

- تمام دسترسی به داده در `assets/js/api.js` است. `app.js` هیچ‌جا مستقیم `fetch` نمی‌کند.
- **مرحله‌ی بدون سرور (پیشنهادی):** سایت مدیریت می‌تواند یک صفحه‌ی HTML جدا باشد که همین JSONها را می‌خواند، فرم ویرایش نشان می‌دهد و با GitHub API فایل را commit می‌کند (با یک Personal Access Token محدود). بدون خرید سرور کار می‌کند.
- **مرحله‌ی بعد با سرور:** در `config.js` مقدار `mode` را `'api'` کنید. سایت به‌جای `data/*.json` از `GET /api/recipes` و بقیه می‌خواند و نظرها را با `POST /api/comments` می‌فرستد. ساختار پاسخ‌ها همان JSON فعلی است.
- **نظرها:** فعلاً نظر بازدیدکننده فقط در مرورگر خودش (localStorage) ذخیره می‌شود. برای نظرهای واقعی که همه ببینند، به سرور یا سرویس فرم نیاز است (حالت `api`).

## ویژگی‌ها

نوار ناوبری چسبان با منوی دسته‌بندی، جستجوی زنده (کلید `/` یا `Ctrl+K`)، منوی کناری، هیرو با بخار و ذرات عطر، کاروسل (کشیدن با انگشت و کلیدهای جهت)، دسته‌بندی‌ها، ویژه‌ها، همه‌ی دستورها با فیلتر، آموزش، تصاویر، آخرین‌ها، بهترین‌ها، نظرات، حالت شب، لینک مستقیم به هر دستور (`#recipe=id`)، چاپ دستور، احترام به `prefers-reduced-motion`.
